# Phase 4 리팩토링 보고서: 디스플레이 성능 최적화 및 I2C 결함 복구 연계

## 1. 개요
기존 시스템은 매 1초마다 변경 여부와 상관없이 LCD1602의 32문자 전체를 I2C 버스를 통해 무조건 반복 전송하고 있었으며, 일시적인 I2C 버스 노이즈나 NACK이 발생하면 드라이버가 영구 비활성화(`initialized = false`)되어 MCU 리셋 전까지 디스플레이가 멈추는 치명적인 취약점이 있었습니다.

또한 PWM LED 제어와 직접적인 관련이 없거나 충돌을 유발할 수 있는 GPIO 기반 레거시 제어 함수들이 남아있었습니다.

Phase 4에서는 LCD1602 Diff 버퍼링, 하드웨어 I2C Bus Recovery 연계, 컴파일러 경고 제로화 및 미사용 코드 정리를 완료하였습니다.

---

## 2. 주요 변경 사항

### 2.1 LCD1602 Diff 렌더링 버퍼링 (`ui_lcd.c`)
- **개선 내용**:
  - `s_prev_line0[17]`, `s_prev_line1[17]` 문자열 캐시 버퍼 도입.
  - 새로 포맷팅된 라인 텍스트와 이전 출력 텍스트를 `strncmp`로 비교.
  - **텍스트가 실제로 변경된 라인에 한해서만** I2C 커서 이동 및 문자열 전송 명령을 수행.
  - 초기화(`uiLcdInit`) 및 절전 모드 복귀(`uiLcdWake`) 시에는 캐시 버퍼를 클리어하여 즉시 전체 화면 재동기화.
- **효과**: 정적 상태(온습도 변화가 적거나 절전 진입 전)에서 I2C 버스 통신 트래픽을 최대 50~90% 절감.

### 2.2 I2C 버스 락업 시 자동 복구 연계 (`bsp_lcd1602.c`, `bsp_i2c.c`)
- **개선 내용**:
  - `i2c_send()`에서 1차 전송 실패 및 1ms 대기 후 재시도까지 실패할 경우, 무조건 드라이버를 비활성화하지 않고 `bsp_i2c.c`의 `i2cBusRecover()`를 트리거.
  - SCL을 최대 9회 토글하여 SDA에 고착된 슬레이브를 해방하고 STOP 조건을 강제 생성한 뒤 I2C1 페리페럴을 재초기화하고 최종 재전송을 수행.
- **효과**: 케이블 노이즈나 전원 지터로 인한 일시적 I2C Stuck 현상 발생 시 시스템 멈춤 없이 자체 복구(Self-healing) 달성.

### 2.3 미사용 코드 및 충돌 함수 정리
- `bsp_gpio.c / h`:
  - 타이머 PWM AF_PP 모드와 충돌하던 GPIO 직제어 함수(`bgrSetColor`, `bgrNextStep`, `bgrInit`) 제거.
  - 온보드 LD2 토글(`ld2Toggle()`) 및 초기화(`gpioInit()`)만 남겨 단일 책임 확립.
- `bsp_timer.c / h`:
  - 미사용 전역 변수 `s_current_duty`, 미사용 함수 `timerSetDutyFloat`, 미사용 구조체 필드 `is_n_channel` 제거.
  - 구조체 초기화 경고 및 `ui_lcd.c` 문자열 버퍼 트렁케이션 경고를 완벽히 수정하여 **0 Warnings** 달성.

## 3. 검증 결과
- **컴파일러**: ARM Clang (AC6 V6.24.0), MicroLib
- **빌드 결과**: **0 Errors, 0 Warnings** (클린 빌드 완료)
- **프로그램 크기**: Code=39684, RO-data=1564, RW-data=216, ZI-data=6584
- **전체 리팩토링 요약**:
  - 하드웨어 안전성(DWT 지연, 핀 모드, TIM 주파수 통일) 확보
  - 유지보수성이 뛰어난 협력형 스케줄러 및 계층적 모듈 분리
  - 하드웨어 독립적인 GFX 라이브러리 분리 및 중복 코드 600줄 이상 제거
  - 자체 복구 가능한 고신뢰성 I2C 디스플레이 통신 구축
